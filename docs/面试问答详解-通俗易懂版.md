## 一、项目深挖题

### 1.1 数仓项目

#### Q1：ODS、DWD、ADS 每层存什么？

**【答】**  
可以记成「由脏到净、由细到粗」：

- **ODS（贴源层）**：和业务系统长得差不多，**尽量少改**，先接住数据。像「原材料仓库」，什么都有。  
- **DWD（明细层）**：清洗、统一字段、去重、规范化。像「洗干净、贴好标签的半成品」。  
- **DWS（汇总层，简历里有）**：按主题做轻度汇总，比如按天、按设备汇总。  
- **ADS（应用层）**：直接给报表、看板用的**指标表**，比如日产量、设备利用率。像「端上桌的菜」。

**【项目】** 我们离线是 ODS→DWD→ADS，ADS 给 Power BI；实时还有 Flink 写 HBase、Redis、Doris。

---

#### Q2：Spark SQL 和 Hive 有什么区别？

**【答】**  
- **Hive**：更像「用 SQL 操作 HDFS 上的大数据」，底层早期常转成 MapReduce，现在也常跑在 Spark 上。强项是**数仓表管理、分区、元数据**。  
- **Spark SQL**：Spark 引擎自带的 SQL，**内存计算多**，适合迭代、复杂 ETL，速度通常更快。

实际项目里经常是：**Hive 建表、管分区**，**Spark SQL 跑重 ETL 和指标**，两者配合，不是二选一。

---

#### Q3：Flink CDC 和 Sqoop 离线同步，怎么选型？

**【答】**  
- **Sqoop**：定时**批量**把 MySQL 等关系库的数据抽到 HDFS/Hive，适合 **T+1 全量/增量**，延迟小时级、天级没问题。  
- **Flink CDC**：**实时读 binlog**，改一条同步一条，延迟秒级，适合**维表变更、实时数仓**。

**【项目】** 离线入 ODS 用 Sqoop/批量；配置表、维表要实时跟业务库一致，用 Flink CDC。

---

#### Q4：广播流为什么能更新维度？

**【答】**  
维表变更流通常数据量不大，但**每个并行任务都要用到最新维度**。  
「广播」就是把这条小流**复制发给所有算子实例**，大家都能收到同一份维表更新，再去关联大流量的事实流，不用每条事实都去查库。

**【类比】** 车间广播通知：一条通知，所有工位同时听到。

---

#### Q5：HBase RowKey 怎么设计？

**【答】**  
RowKey 决定数据**落在哪个 Region、怎么扫描**。

常见原则：  
1. **避免热点**：别都用连续时间戳开头，否则都写同一 Region。可把设备 ID 放前面，或加盐。  
2. **满足查询**：最常查的条件放进 RowKey 前缀，比如 `设备ID_时间`。  
3. **长度适中**：别太长浪费空间。

**【项目】** 维表按业务主键 + 时间或版本设计，保证按 key 点查和范围扫都合理。

---

#### Q6：Doris 和 ClickHouse 了解吗？

**【答】**  
都是 **OLAP 分析型数据库**，列式存储，适合聚合、报表，比 MySQL 擅长大宽表统计。

- **ClickHouse**：查询极快，运维和生态在国内很火。  
- **Doris**：MPP 架构，兼容 MySQL 协议，国内数仓项目里也常见。

**【项目】** 我们 DWS 聚合结果写 **Doris** 做分析；ClickHouse 原理类似，都是「分析专用库」。

---

#### Q7：Power BI 数据从哪来？

**【答】**  
从数仓 **ADS 层指标表** 来——Spark SQL 算好的结果表，配置到 Power BI 数据源（直连或定时刷新）。  
要保证 **ADS 字段口径** 和 SQL 一致，否则看板数字会对不上。

---

#### Q8：数据口径不一致怎么处理？

**【答】**  
1. **先统一规则**：字段名、单位、枚举值、计算公式写成文档。  
2. **在 DWD 落地**：清洗时做映射、校验，脏数据打标或过滤。  
3. **对账**：用抽样 SQL 和业务报表、源库比对 count、sum。  
4. **改口径走变更流程**：别悄悄改 ADS，避免历史不可比。

**【项目】** 多源工业数据口径乱，我们制定了统一字段规范，DWD 统一后再出 ADS。

---

### 1.2 新闻推荐

#### Q1：冷启动怎么办？

**【答】**  
新用户没有行为，协同过滤算不出来，叫**冷启动**。

常见做法：  
1. **热门榜**：全员看点击量最高的新闻（Redis ZSet）。  
2. **默认列表**：编辑精选或类目头条。  
3. 有一点行为后，再切到个性化。

**【项目】** 接口先读用户 Redis 候选，没有就**热门榜兜底**，再没有就 MySQL 默认列表，保证首屏不空。

---

#### Q2：协同过滤稀疏性是什么？你怎么处理？

**【答】**  
用户只点过少数新闻，矩阵里**大量空白**，算相似度不准，叫**稀疏**。

处理：  
- **ItemCF / UserCF** 选适合场景的；  
- 加 **内容相似度**（标签、向量）补一路召回；  
- **热门兜底**；  
- 对新内容用 **content-based** 先推。

**【项目】** 多路召回：协同过滤 + 内容相似度，合并去重写 Redis。

---

#### Q3：Kafka 消息积压怎么处理？

**【答】**  
积压 = 生产太快或消费太慢，Topic 里消息堆着。

处理思路：  
1. **加消费者实例**（不超过分区数）。  
2. **加 Topic 分区**，提高并行。  
3. **优化消费逻辑**，别在循环里慢 SQL。  
4. 临时**扩容**，事后查为什么突然流量变大。  
5. 实在来不及可**丢弃极旧数据**（业务允许时）。

---

#### Q4：Redis 和 MySQL 行为数据一致性？

**【答】**  
要接受：**实时链路是最终一致**，不是强一致。

- **MySQL**：持久化、后台查历史，准。  
- **Kafka**：给 Streaming 算实时偏好。  
- **Redis**：给推荐接口读，要快。

接口以 **Redis 为准** 做展示；对账用 MySQL 统计。消费失败要重试，避免 Kafka 丢了 MySQL 有。

---

#### Q5：ECharts 词云数据从哪来？

**【答】**  
后端用 SQL 统计**高频关键词**（标题、标签分词后 count），接口返回 JSON 列表 `{name, value}`，前端 ECharts **wordCloud** 组件渲染。  
口径要和运营约定：统计哪段时间、是否去停用词。

---

### 1.3 百味智厨

#### Q1：pgvector 和 Elasticsearch 怎么选？

**【答】**  
都做**向量检索**，RAG 里二选一或组合。

- **pgvector**：PostgreSQL 插件，**业务和向量一张库**，运维简单，适合中等规模知识库。  
- **ES**：搜索强、生态成熟，大数据量、复杂全文+向量混合时更合适。

**【项目】** 我用 **pgvector + Spring AI PgVectorStore**，菜谱 Markdown 规模适中，和会话表同库好管理。

---

#### Q2：向量维度多少？

**【答】**  
和 **Embedding 模型输出** 一致。百味智厨接百炼 Embedding，当前配置 **1024 维**。维数不一致会入库失败，改模型要重建向量表或重新导入。

---

#### Q3：如何防止大模型胡编？

**【答】**  
1. **RAG**：先检索菜谱再回答，减少瞎编。  
2. **Query 改写**：口语问题改写成好检索的句子。  
3. **温度调低**：生成更保守。  
4. **固定测试集回归**：改 prompt/切块后跑一遍。  
5. **结构化输出**：膳食报告用 `.entity()` 限定格式。  
6. 回答里要求**基于检索内容**，检索为空就说不知道。

---

#### Q4：SSE 和 WebSocket 区别？

**【答】**  
- **SSE**：基于 HTTP，**服务器单向**推流给浏览器，实现简单，适合 AI **逐字输出**。EventSource 不好带 Header，我们常把 token 放 URL 参数。  
- **WebSocket**：**双向**长连接，适合聊天室、游戏。

**【项目】** 烹饪助手 `/chef_app/chat/sse` 用 SSE + `Flux` 流式返回。

---

#### Q5：JWT 过期怎么处理？

**【答】**  
登录时发 token，设**过期时间**（如 2 小时）。  
- 前端：401 时**跳转登录**或调刷新接口（若有 refresh token）。  
- 后端：`AuthInterceptor` 校验失败返回 401 + 明确错误信息。  
- 敏感操作可缩短过期时间。

**【项目】** `JwtUtil` 生成 token，拦截器解析 `userId`；SSE 用 `?token=` 传参。

### Day2 新闻推荐（5 题全答）

**Q：推荐接口怎么设计？**  
`GET /recommend?userId=` → Redis 用户 List → 无则热门 ZSet → 再无默认列表 → 分页。异常不 500，给兜底内容。

**Q：为什么 MySQL 又 Kafka？**  
MySQL：持久化、后台、对账。Kafka：解耦、给 Spark Streaming 实时算。各干各的，不互相拖慢。

**Q：协同过滤怎么做？**  
用户-新闻行为矩阵 → 算用户相似或物品相似 → Top-N → 与内容相似度合并 → 写 Redis。

**Q：Redis 存什么？**  
推荐 List、热门 ZSet、偏好 Hash；设 TTL。

**Q：为什么用 Spark Streaming 不用 Flink？**  
秒级够用、和 Spark 离线统一、团队熟悉；毫秒级再考虑 Flink。

### Day6 模拟连问（3 题）

**Q：Spark 数据倾斜怎么处理？**  
先找**哪个 key 特别大**。然后：加盐打散再聚合、过滤异常 key、小表**广播 Join**、调大 shuffle 分区仅缓解。数仓项目里设备 ID 热点用过加盐。

**Q：Flink CDC 和 Canal 区别？**  
都是读 MySQL binlog 做同步。**Canal** 常作独立同步工具，推 MQ 或下游。**Flink CDC** 和 Flink 作业一体，适合在流里直接做 Join、聚合。选型看是否要进 Flink 实时计算链路。

**Q：Hive 分区字段怎么选？**  
选查询**必带**的条件，如 `dt`（日期）、`region`。分区太多太细会小文件多；太粗扫描量大。一般按天分区，再按业务需要加分区字段。

## 三、Java 基础八股

### 1. == 和 equals 有什么区别？

**【答】**  
`==` 比较的是不是**同一个对象**（基本类型比值）。  
`equals` 比较**内容是否相等**（要看类有没有重写）。  
String 比较内容用 `equals`，别用 `==`（除非确定是常量池同一对象）。

---

### 2. HashMap 原理？

**【答】**  
数组 + 链表 + 红黑树（JDK8+）。  
先算 key 的 hash 找桶位置；冲突就链起来；链表太长变红黑树。  
默认负载因子 0.75，超了就扩容翻倍。

---

### 3. HashMap 线程安全吗？

**【答】**  
**不安全**。多线程同时 put 可能丢数据或死循环（老版本）。  
并发用 **ConcurrentHashMap**，分段或 CAS+synchronized 保证安全。

---

### 4. ArrayList 和 LinkedList？

**【答】**  
- **ArrayList**：底层数组，**按下标查快**，中间插删要挪元素。  
- **LinkedList**：双向链表，**头尾插删快**，查要遍历慢。  
一般列表用 ArrayList 更多。

---

### 5. 线程池七个参数？

**【答】**  
1. 核心线程数  
2. 最大线程数  
3. 存活时间（非核心线程空闲多久回收）  
4. 时间单位  
5. **工作队列**（任务排队的地方）  
6. 线程工厂（命名等）  
7. **拒绝策略**（队列满了怎么办：抛异常、调用者跑、丢弃等）

**【人话】** 核心员工 + 临时工 + 等候区 + 爆满时的处理规矩。

---

### 6. synchronized 和 Lock？

**【答】**  
都能加锁。  
- **synchronized**：JVM 关键字，自动释放，写法简单。  
- **Lock（如 ReentrantLock）**：可**尝试锁**、可中断、可公平、多条件队列，要手动 unlock。

---

### 7. volatile 干什么？

**【答】**  
保证**可见性**（一个线程改了，别的线程能马上看到）和**禁止部分重排序**。  
**不保证** i++ 这种复合操作的原子性。  
适合状态标志位；计数还要 Atomic 或锁。

---

### 8. 死锁四个条件？

**【答】**  
1. 互斥  
2. 占有且等待  
3. 不可抢占  
4. 循环等待  

打破任一即可避免，比如**固定加锁顺序**、用超时 tryLock。

---

### 9. 接口和抽象类？

**【答】**  
- **接口**：多实现，以前只能抽象方法，JDK8+ 可有 default 方法；更像「能力合同」。  
- **抽象类**：单继承，可以有成员变量和已实现方法；更像「半成品父类」。

---

### 10. 深拷贝和浅拷贝？

**【答】**  
- **浅拷贝**：对象复制了，但里面的**引用还是同一份**（改内部对象会互相影响）。  
- **深拷贝**：里面引用的对象也**递归复制**，完全独立。

---

### 11. String 为什么不可变？

**【答】**  
内部 char/byte 数组 final，改不了内容。好处：**线程安全**、可以做**字符串常量池**、hash 稳定适合当 HashMap 的 key。

---

### 12. JVM 内存结构？

**【答】**  
- **堆**：对象实例（垃圾回收主战场）  
- **栈**：方法调用、局部变量（每个线程一份）  
- **方法区/元空间**：类信息、常量  
- **程序计数器**：当前执行到哪一行  
- **本地方法栈**：native 方法  

---

### 13. 垃圾回收算法？

**【答】**  
标记谁还活着，回收死的。常见：  
- **标记-清除**（有碎片）  
- **复制**（新生代常用）  
- **标记-整理**（老年代常用）  
实际用**分代收集**：新生代、老年代不同策略。知道 CMS、G1 名字即可。

---

### 14. 类加载过程？

**【答】**  
加载 → 验证 → 准备 → 解析 → 初始化。  
**加载**：读 class 文件；**初始化**：执行静态代码块等。  
双亲委派：先让父加载器加载，避免重复、保证核心类安全。

---

### 15. 反射？

**【答】**  
运行时才知道类名，也能**动态创建对象、调方法**。  
框架（Spring、MyBatis）大量用。缺点：慢、破坏封装，业务代码少用。

---

## 四、Spring / Spring Boot

### 1. IOC 是什么？

**【答】**  
**控制反转**：对象的创建和依赖关系交给 **Spring 容器**，不是你 new。  
你要什么，容器**注入**进来（DI）。好处：解耦、好测试、统一管理生命周期。

---

### 2. AOP 是什么？

**【答】**  
**面向切面**：日志、事务、权限这种横切逻辑，单独写「切面」，自动织入到很多方法上，不用每个方法复制粘贴。  
像给所有接口统一包一层「前后处理」。

---

### 3. Bean 生命周期（简化）？

**【答】**  
实例化 → 属性注入 → 初始化（@PostConstruct）→ 使用 → 销毁。  
面试说到「容器创建、注入依赖、初始化回调」就够。

---

### 4. 循环依赖怎么办？

**【答】**  
两个 Bean 互相要对方。Spring 用**三级缓存**让单例 Bean 能提前暴露「半成品」解决**setter 注入**的循环。  
**构造器注入**循环依赖解决不了，要改设计。

---

### 5. @Autowired 和 @Resource？

**【答】**  
都是注入。  
- **@Autowired**：Spring 的，默认**按类型**  
- **@Resource**：Java 的，默认**按名称**  

---

### 6. Spring Boot 优点？

**【答】**  
自动配置（少写 XML）、内嵌 Tomcat（jar 就能跑）、starter 依赖一把拉齐、配置简单。  
**快速搭项目**，百味智厨、新闻推荐都是 Spring Boot。

---

### 7. RESTful？

**【答】**  
用 URL 表示**资源**，用 HTTP 方法表示动作：GET 查、POST 增、PUT/PATCH 改、DELETE 删。  
状态码要有意义：200 成功、401 未登录、404 没有、500 服务端错。

---

### 8. @Transactional 什么时候失效？

**【答】**  
常见坑：  
1. 方法不是 **public**  
2. **同类里自调用**（没走代理）  
3. 异常被 catch 吃了没抛出  
4. 抛的是**受检异常**但没配置 rollback  
5. 类没被 Spring 管理  

---

### 9. MyBatis 原理？

**【答】**  
Mapper 接口 → JDK 动态代理 → 找到对应 SQL（XML 或注解）→ SqlSession → JDBC 执行 → 结果映射成 Java 对象。  
你只写接口和 SQL，框架帮你连库。

---

### 10. Filter 和 Interceptor？

**【答】**  
- **Filter**：Servlet 规范，在进 Spring 之前就能拦（编码、跨域等）。  
- **Interceptor**：Spring MVC 的，拦 Controller 前后。  

**【项目】** JWT 用 **AuthInterceptor** 拦接口。

## 五、MySQL

### 1. 为什么索引用 B+ 树？

**【答】**  
树矮、一层存很多 key，**磁盘 IO 少**；叶子节点链表串起来，**范围查询**（between、排序）很顺；非叶子只存 key，省空间。

---

### 2. 聚簇索引？

**【答】**  
InnoDB 里，**叶子节点就是整行数据**。一张表主要靠一个聚簇索引（一般是主键）。  
二级索引叶子存的是**主键值**，还要回表查一次。

---

### 3. 最左前缀？

**【答】**  
联合索引 (a, b, c)，查询条件要从**最左边 a 开始用**才走索引；只查 b、c 可能用不上。

---

### 4. 覆盖索引？

**【答】**  
查询的列**都在索引里**，不用回表，更快。比如索引 (user_id, create_time)，只查这两列。

---

### 5. 事务隔离级别？

**【答】**  
读未提交、读已提交、**可重复读**（MySQL 默认）、串行化。  
校招重点：**可重复读** + MVCC；还要知道**脏读、不可重复读、幻读**各是什么。

---

### 6. 脏读、幻读？

**【答】**  
- **脏读**：读到别人还没提交的数据。  
- **不可重复读**：同一事务里读两次，中间别人**改了**同一行。  
- **幻读**：同一条件读两次，**行数变了**（别人插入或删除）。

---

### 7. 慢 SQL 怎么优化？

**【答】**  
1. `EXPLAIN` 看有没有走索引、扫了多少行  
2. 加/改索引，避免函数包住索引列  
3. 别 `select *`  
4. 深分页改游标或延迟关联  
5. 数据量实在大考虑分表、归档  

**【项目】** 新闻表可对 `user_id + create_time` 建联合索引。

---

### 8. 主从复制？

**【答】**  
主库写 binlog，从库拉过来重放，实现读写分离和备份。  
延迟时：读从库可能略旧，金融类要慎用从库读实时数据。

---

### 9. 存储过程？

**【答】**  
把多条 SQL **写在数据库里**成一个过程，一次调用执行。适合固定报表、批量更新；缺点是难版本管理、移植性差。  
简历写了：可说「复杂统计在库里封装，减少网络往返」。

---

### 10. 视图？

**【答】**  
**虚拟表**，本质是保存好的 SELECT。简化复杂查询、可做权限控制（只给用户看视图）。

---

## 六、计算机网络

### 1. TCP 和 UDP？

**【答】**  
- **TCP**：可靠、有序、有连接，像打电话，HTTP 基于 TCP。  
- **UDP**：不保证可靠，快、简单，像发短信，视频、DNS 常用。

---

### 2. 三次握手？

**【答】**  
建立连接：客户端 SYN → 服务端 SYN+ACK → 客户端 ACK。  
确认双方都能收能发，防止旧连接干扰。

---

### 3. 四次挥手？

**【答】**  
关闭连接：双方都要说「我发完了」「我知道了」，所以四次。  
TIME_WAIT 要等一会儿，防旧包影响新连接。

---

### 4. HTTP 和 HTTPS？

**【答】**  
HTTPS = HTTP + **TLS 加密**，防窃听篡改。线上接口、登录必须用 HTTPS。

---

### 5. GET 和 POST？

**【答】**  
语义上 GET **查询**（可缓存、参数在 URL），POST **提交**（表单、创建资源，body 里带数据）。  
实际开发都重要，别用 GET 带敏感信息。

---

### 6. 常见状态码？

**【答】**  
200 成功；301/302 跳转；400 请求错了；**401 未登录**；403 没权限；404 没有；500 服务器挂了；502 网关后面挂了。

---

### 7. Cookie 和 Session？

**【答】**  
- **Cookie**：存在**浏览器**的小文本，下次请求自动带上。  
- **Session**：存在**服务器**的会话，浏览器只拿一个 SessionId（常放 Cookie）。  

JWT 则是「无状态」，token 里带信息，服务器少存 Session。

---

### 8. 浏览器输入 URL 后发生什么？

**【答】**  
DNS 解析域名 → TCP 连接 → 发 HTTP 请求 → 服务器返回 → 浏览器解析 HTML/CSS/JS 渲染。  
HTTPS 中间还有 TLS 握手。

---

### 9. SSE 是什么？

**【答】**  
**Server-Sent Events**：服务器通过 HTTP **一直推**数据给浏览器，单向。  
适合 AI 打字机效果。百味智厨流式对话用的就是这个。

---

## 七、Redis

### 1. 五种数据类型？

**【答】**  
String（字符串/计数）、List（列表）、Hash（对象字段）、Set（去重集合）、ZSet（带分数，排行榜）。  
推荐里：List 存候选、ZSet 存热门、Hash 存偏好。

---

### 2. RDB 和 AOF？

**【答】**  
- **RDB**：定时**快照**，恢复快，可能丢最近几分钟。  
- **AOF**：记**每条写命令**，更全，文件大要重写。  
生产常**混合**用。

---

### 3. 过期策略？

**【答】**  
key 设了 TTL 到期删。Redis **定期抽样删** + **访问时发现过期再删**（惰性）。不是每秒扫全部 key。

---

### 4. 缓存穿透？

**【答】**  
查**根本不存在**的数据，缓存没有，每次都打穿到 DB。  
解决：**布隆过滤器**挡一层；或缓存**空值**（短 TTL）。

---

### 5. 缓存击穿？

**【答】**  
**热点 key 过期**瞬间，大量请求一起打 DB。  
解决：互斥锁只放一个线程查库；或**逻辑过期**（数据不过期，异步更新）。

---

### 6. 缓存雪崩？

**【答】**  
**大量 key 同时过期**或 Redis 挂了，DB 扛不住。  
解决：过期时间**加随机**、集群高可用、限流降级。

---

### 7. 多级缓存？

**【答】**  
Caffeine（本机）→ Redis（共享）→ 数据库。  
先快后慢，查到后回填上层。数仓维表、推荐、学习模块都能套这个思路。

---

### 8. Redisson 锁？

**【答】**  
基于 Redis 的**分布式锁**，多实例部署时同一资源只让一个实例执行。  
比手写 SETNX 省心：可重入、**看门狗自动续期**防业务没跑完锁就过期。

---

### 9. Redis 为什么快？

**【答】**  
数据在**内存**；单线程避免锁竞争（6+ 也有 IO 线程）；**IO 多路复用**；简单数据结构。  
适合读多写少、缓存场景。

---

### 10. Redis 集群？

**【答】**  
主从复制 + 哨兵自动故障转移；或 **Cluster** 分片扩容。  
面试知道「主从、哨兵、分片」三个词即可。

---

## 八、Kafka

### 1. 架构？

**【答】**  
**Producer** 发消息到 **Topic**（分 **Partition** 并行），存在 **Broker** 上；**Consumer Group** 里消费者分工读，一条消息组内只被一个消费者处理。

---

### 2. 为什么快？

**【答】**  
顺序写磁盘、批量、压缩、零拷贝等技术，适合**高吞吐日志流**。  
别和传统 MQ 比「功能多」，Kafka 强项是吞吐和持久化。

---

### 3. 消息不丢？

**【答】**  
生产者 `acks=all` 等副本确认；Broker 多副本；消费者**处理完再提交 offset**（手动提交更稳）。

---

### 4. 重复消费？

**【答】**  
消费完宕机，offset 没提交，会再消费一次。  
解决：业务**幂等**（唯一键、去重表）、或接受至少一次语义。

---

### 5. 积压？

**【答】**  
见新闻推荐 Q3。

---

### 6. 和 RabbitMQ？

**【答】**  
Kafka：**日志、大数据、高吞吐**（行为流、数仓管道）。  
RabbitMQ：路由灵活、延迟队列，传统业务 MQ 多。

---

### 7. 分区策略？

**【答】**  
指定 key 则 **hash 到固定分区**（同 key 有序）；否则轮询。  
分区数决定最大并行消费数。

---

### 8. ISR？

**【答】**  
和 Leader **保持同步**的副本集合。只有 ISR 里副本都 ACK，才算可靠写入（acks=all 时）。

---

## 九、Spark

### 1. RDD 特点？

**【答】**  
弹性分布式数据集：**分区**、**不可变**、可 lineage 容错。  
算子分转换（map）和行动（collect），行动才真正执行。

---

### 2. 宽窄依赖？

**【答】**  
- **窄**：父分区最多被一个子分区用，如 map，**无 shuffle**。  
- **宽**：多个父分区进一个子分区，如 groupBy，要 **shuffle**，贵。

---

### 3. Stage 怎么划分？

**【答】**  
**Shuffle 边界**切开 Stage，一个 Stage 里流水线执行，减少 IO。

---

### 4. 数据倾斜？

**【答】**  
见 Day6。加盐、广播小表、过滤异常 key。

---

### 5. cache 和 persist？

**【答】**  
把 RDD/DataFrame **存内存或磁盘**，下次用不用重算。persist 可选存储级别（内存 only、内存+磁盘等）。

---

### 6. Spark SQL？

**【答】**  
用 SQL 或 DataFrame API 写逻辑，**Catalyst 优化器**优化执行计划，底层还是 Spark 跑。

---

### 7. Spark Streaming？

**【答】**  
**微批**：每隔几秒把流数据当一小批 RDD 算，延迟秒级，和 Spark 生态统一。新闻推荐用的这个。

---

### 8. 和 MapReduce？

**【答】**  
MR 每步落盘，慢；Spark **内存迭代**快很多。老项目 MR，新项目多用 Spark。

---

## 十、Flink

### 1. Flink 特点？

**【答】**  
**真流式**、低延迟、带**状态**、支持 **Checkpoint** 容错，适合实时数仓、CDC、实时大屏。

---

### 2. Checkpoint？

**【答】**  
定时给整个作业拍**分布式快照**，挂了从上次快照恢复，像游戏存档。

---

### 3. Watermark？

**【答】**  
告诉系统「事件时间大概到哪儿了」，**允许数据迟到一点**再触发窗口，乱序流必备。

---

### 4. 状态？

**【答】**  
算子记住之前算过什么（如累计、去重）。**KeyedState** 按 key 隔离；太大要调状态后端和 TTL。

---

### 5. Flink CDC？

**【答】**  
见数仓部分，读 binlog 实时同步。

---

### 6. 和 Spark Streaming？

**【答】**  
Flink：**来一条处理一条**（事件驱动），延迟更低。  
Streaming：**攒一批算一批**，秒级，开发简单。  
实时数仓、CDC 更常 Flink；和 Spark 离线统一则 Streaming。

---

### 7. 背压？

**【答】**  
下游处理慢了，压力会**往回传**，上游自动降速，防止撑爆。Flink 原生支持较好。

---

### 8. 广播流？

**【答】**  
见数仓 Q4。

---

## 十一、Hive

### 1. Hive 本质？

**【答】**  
让你用 **SQL 查 HDFS 上的大数据**，表元数据在 Metastore，执行可能是 MapReduce/Spark/Tez。

---

### 2. 分区和分桶？

**【答】**  
- **分区**：按日期、地区等**分文件夹**，查询带条件只扫某分区，快。  
- **分桶**：分区内再 hash 分文件，优化 join 和采样。

---

### 3. 开窗函数？

**【答】**  
`row_number()`、`rank()`、`sum() over(partition by ... order by ...)`  
**不合并行**，每行还在，旁边多一列排名或累计。去重、TopN 常用。

---

### 4. sort by / distribute by？

**【答】**  
`distribute by` 控制**哪些 key 去同一 reducer**；`sort by` 分区内排序。  
集群调优用，日常 SQL 写分区 + 开窗更多。

---

### 5. 小文件？

**【答】**  
见数仓；合并、控制输出、合理分区。

---

### 6. Join 优化？

**【答】**  
**小表放 Map Join**（广播到各节点），避免大表对大表 shuffle。

---

### 7. Explain？

**【答】**  
看执行计划：有没有全表扫、Join 类型、Stage。  
优化前先看 Explain，别瞎加索引式思维到 Hive。

---

## 十二、AI / Spring AI

### 1. 什么是 RAG？

**【答】**  
**检索增强生成**：先从你的知识库**搜相关段落**，再交给大模型组织语言回答。  
模型不用背下整本菜谱，**减少胡编**，知识更新改文档就行。

---

### 2. Embedding？

**【答】**  
把文字变成**一串数字（向量）**，意思相近的文字，向量距离近。  
用来「按语义搜」，不是只匹配关键词。

---

### 3. 向量检索？

**【答】**  
问题也变成向量，在向量库里找**最近的 topK 条**文档。  
常用余弦相似度；数据量大用 HNSW 等近似索引加速。

---

### 4. Prompt 注入（RAG 里）？

**【答】**  
把检索到的菜谱片段**塞进提示词**里，告诉模型：「请根据以下内容回答」。  
不是 SQL 注入，是**给模型上下文**。

---

### 5. Tool Calling？

**【答】**  
模型判断「我要调哪个工具」，比如搜索、写文件；框架执行 Java 方法，把结果**再塞回对话**，模型继续生成。  
百味智厨 `@Tool` 搜索、PDF 就是这样。

---

### 6. MCP？

**【答】**  
**模型上下文协议**，统一方式接**外部工具/服务**（如图床、生图 API）。  
和本地 @Tool 比，MCP 是**远程服务**，用 HTTP 等协议连。

---

### 7. ReAct？

**【答】**  
**Reason + Act**：先想一步 → 调工具 → 看结果 → 再想，循环直到任务完成。  
ChefManus 智能体是这个模式。

---

### 8. Spring AI 核心组件？

**【答】**  
**ChatClient** 调模型；**ChatModel** 模型抽象；**Advisor** 增强链（记忆、RAG、日志）；**VectorStore** 向量库；**ToolCallback** 工具。  
百味智厨全套都在用。

---

### 9. 幻觉怎么减？

**【答】**  
见百味智厨 Q3；RAG + 低温度 + 测试集 + 检索为空就说不知道。

---

### 10. Token 成本怎么控？

**【答】**  
缩短 system prompt；RAG 只塞相关片段；**缓存**相同问题；简单任务用小模型；流式先返回提升体验。

---

## 十三、操作系统 + 大数据组件

### 操作系统

**进程 vs 线程？**  
进程是资源单位（内存空间）；线程是 CPU 调度单位，同一进程内线程共享内存。线程更轻，但要小心共享数据加锁。

**死锁？**  
见 Java 第 8 题；OS 层还会讲银行家算法（了解即可）。

**虚拟内存？**  
让每个进程以为自己有很大内存，实际映射到物理内存+磁盘，不够就换页。

---

3～5 年：往 **【数据平台、架构或 AI 工程化】** 发展，数据和工程结合。  
不频繁跳槽，希望在一家公司把链路吃透。

---

### 6. 三个项目哪个最熟？

**【答】**  
**数仓和新闻推荐**投入时间最长，Spark/Flink/Redis/Kafka 能讲链路。  
**百味智厨**是我主动做的 AI 工程，RAG 和 Agent 能演示代码。  
根据岗位：大数据岗前两个多讲，AI 岗第三个多讲。

---

### 7. 为什么专业大数据却做 AI / 后端？

**【答】**  
大数据解决「数据从哪来、怎么算」；后端和 AI 解决「怎么服务用户」。  
RAG 本质是**检索+数据**；推荐是**行为数据+接口**。  
一条技术线，只是表层应用不同。

见复习计划 **§11**（模块/需求/测试手册）。

### 9. 简历和岗位不一样，为什么投？

### 10. Spring AI 和 Spring AI Alibaba？

**【答】**  
Spring AI 是**通用框架**（ChatClient、RAG、Tool）。  
Spring AI Alibaba 是**接阿里云百炼**的扩展，注入 `dashScopeChatModel` 就能用通义。  
LangChain4j 是另一套框架，我项目**主用 Spring AI**。
