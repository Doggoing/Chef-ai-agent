1. **先背「面试口述版」**，追问再展开「你怎么用」。
2. 带 **【项目】** 的条目，优先结合你的数仓 / 新闻推荐 / 百味智厨讲。

## 一、编程语言

### 1.1 Java 语言

**是什么？**  
写后端业务的主流语言，跨平台（JVM），生态成熟，做 Web、大数据（Spark/Flink 也支持 Java）都行。

**类比：** 像「通用施工语言」，盖 Web 房子、接数据管道都能用。

**你怎么用？【项目】**  
- 新闻推荐、百味智厨的后端都是 **Java + Spring Boot**  
- 数仓里 Spark/Flink 任务、Maven 工程也是 Java 体系  

**面试口述版：**  
> Java 是我主要开发语言。后端用 Java 写业务逻辑和接口；大数据侧用 Java 写 Spark/Flink 任务和 Maven 工程。熟悉集合、异常、面向对象这些基础，能独立完成后端模块开发。

**常追问：**

| 问题 | 通俗答 |
|------|--------|
| Java 和 JavaScript 区别？ | Java 编译后在 JVM 跑，多用于后端；JS 多在浏览器跑，做前端。 |
| JDK、JRE、JVM？ | JVM 是运行环境；JRE = JVM+类库；JDK = JRE+开发工具（编译器等）。 |

---

### 1.2 Hutool

**是什么？**  
国产 **Java 工具类库**，把日常开发里重复的活（判空、读文件、发 HTTP、生成 ID）封装成现成方法，少写样板代码。

**类比：** 像「瑞士军刀」，不用自己造轮子，直接拿工具用。

**你怎么用？【项目 · 百味智厨】**  

| Hutool 类/方法 | 干什么 | 代码位置（示例） |
|----------------|--------|------------------|
| `StrUtil` | 字符串判空、裁剪 | `ChatConversationService`、`BaseAgent` |
| `IdUtil` | 生成会话 ID 等唯一编号 | `ChatConversationService` |
| `FileUtil` | 读写文件、创建目录 | `FileOperationTool`、`PDFGenerationTool` |
| `HttpUtil` | 发 HTTP 请求 | `WebSearchTool`、`ResourceDownloadTool` |
| `JSONUtil` / `JSONObject` | 解析 JSON | `WebSearchTool` |
| `CollUtil` | 集合判空、操作 | `ToolCallAgent` |

**面试口述版：**  
> Hutool 是 Java 工具库，我用来提高开发效率。比如用 **StrUtil** 做字符串判空，**IdUtil** 生成会话 ID，**HttpUtil** 在联网搜索工具里调第三方 API，**FileUtil** 做文件读写和 PDF 生成，**JSONUtil** 解析搜索返回的 JSON。相当于不用手写一堆工具方法，代码更简洁。

**常追问：**

| 问题 | 通俗答 |
|------|--------|
| 和 Apache Commons 区别？ | 都是工具库；Hutool 国内文档多、API 更贴近国内开发习惯，项目里引入方便。 |
| 为什么不用自己写？ | 重复、易错；成熟工具库经过验证，专注业务逻辑即可。 |

---

### 1.3 Lombok

**是什么？**  
通过**注解**在编译期自动生成 getter/setter、构造方法、日志等代码，减少手写「样板代码」。

**类比：** 像 Word 的「自动目录」——你写标题，格式自动生成。

**你怎么用？【项目 · 百味智厨】**  

| 注解 | 作用 | 常见位置 |
|------|------|----------|
| `@Data` | 实体/DTO 的 getter/setter 等 | `SysUser`、`LoginRequest`、各 VO |
| `@Slf4j` | 自动生成 `log` 日志对象 | `ChefApp`、`ChefManus`、各 Service |
| `@RequiredArgsConstructor` | 为 `final` 字段生成构造器，配合注入 | `UserService`、`AuthController` |
| `@AllArgsConstructor` | 全参构造 | `AuthResponse` 等 |

**面试口述版：**  
> Lombok 用注解减少重复代码。实体类用 **@Data** 不用手写 getter/setter；类上加 **@Slf4j** 直接打日志；Service 用 **@RequiredArgsConstructor** 配合构造器注入，代码更干净。百味智厨里 DTO、Entity、Controller 都在用。

**常追问：**

| 问题 | 通俗答 |
|------|--------|
| 原理？ | 编译时注解处理器生成字节码，IDE 里看起来像「有方法」，其实是 Lombok 生成的。 |
| 缺点？ | 过度依赖可能降低可读性；团队要统一 IDE 装 Lombok 插件。 |

---

### 1.4 Knife4j

**是什么？**  
基于 **OpenAPI（Swagger）** 的 **API 文档 + 在线调试** 工具，浏览器里能看接口说明、直接试调接口。

**类比：** 像「接口说明书 + 试用按钮」，前后端联调不用反复问字段格式。

**你怎么用？【项目 · 百味智厨】**  
- `pom.xml` 引入 `knife4j-openapi3-jakarta-spring-boot-starter`  
- `application.yml` 配置 Swagger/Knife4j  
- 启动后访问 Swagger UI，调试 `AuthController`、`AiController` 等  

**面试口述版：**  
> Knife4j 是 Swagger 的增强版，用来生成 REST 接口文档。我在 Spring Boot 项目里集成后，可以在网页上看到每个接口的路径、参数、返回值，还能在线调试，和 Postman 类似但和代码注解同步，联调更方便。

**常追问：**

| 问题 | 通俗答 |
|------|--------|
| 和 Postman 区别？ | Postman 是独立客户端；Knife4j 文档跟代码注解绑定，改代码文档跟着变。 |
| 生产环境暴露吗？ | 一般测试/开发开，生产会关掉或加权限，避免接口信息泄露。 |

---

### 1.5 Scala

**是什么？**  
跑在 JVM 上的语言，**面向对象 + 函数式** 都支持，Spark/Flink 早期 API 和大量大数据示例用 Scala 写。

**类比：** 和 Java 用同一个「 JVM 电厂」，但语法更简洁，适合写数据处理脚本。

**你怎么用？【项目 · 数仓 / Spark】**  
- 简历：大数据场景下用 Scala 做数据开发  
- 实际面试可说：Spark SQL 以 SQL 为主，部分 Spark 任务/课程实验用 Scala 或 Java  

**面试口述版：**  
> Scala 我主要用于大数据课程和 Spark 相关开发。它集合操作和函数式写法简洁，适合 ETL 和数据转换。我熟悉基本语法和集合 API，能读懂和编写 Spark 相关的 Scala 任务；日常工程里 Spark 也常用 SQL 或 Java。

**⚠️ 若 Scala 写得少：** 说「能读能改，复杂任务以 Spark SQL 为主」。

## 二、数据库

### 2.1 MySQL

**是什么？**  
最流行的**关系型数据库**，数据存表里，用 SQL 增删改查，适合业务系统（用户、订单、新闻等）。

**类比：** 像 Excel 很多张关联表，但支持高并发、事务、索引。

**你怎么用？【项目】**  
- **新闻推荐**：用户、新闻、行为表；推荐业务持久化  
- **数仓**：业务源库；Flink CDC 监听 **binlog**  
- **百味智厨**：简历写 MyBatis，业务库也可用 MySQL；当前项目用 **PostgreSQL**（同类关系库，面试可说明）  

**面试口述版：**  
> MySQL 我用来存业务数据，会做表设计、SQL 编写和索引优化。新闻项目里存用户和行为；数仓里 MySQL 是源库，用 CDC 同步。我会用 EXPLAIN 看执行计划，避免全表扫描，必要时加联合索引。

**子技能通俗解释：**

| 简历写的 | 通俗解释 | 面试怎么说 |
|----------|----------|------------|
| **数据库建模** | 设计有哪些表、字段、主外键 | 先画 ER 图，比如用户 1-N 会话、会话 1-N 消息 |
| **索引优化** | 给查询快的「目录」，避免全表扫 | 常查条件建索引；联合索引注意最左前缀 |
| **执行计划 EXPLAIN** | 看 MySQL 打算怎么查这条 SQL | 看 type 是否 index/range，rows 是否过大 |
| **存储过程** | 把多条 SQL 封装在数据库里一次执行 | 复杂统计或批量更新时用，项目里视情况使用 |
| **触发器** | 表数据变更时自动执行一段逻辑 | 如 insert 后写日志表；实际项目用得少，知道原理即可 |
| **视图** | 虚拟表，封装复杂查询 | 给报表或权限简化查询，底层还是真实表 |

### 2.2 Redis

**是什么？**  
**内存数据库**，读写极快，常用作**缓存**、计数、排行榜、分布式锁，多实例共享。

**类比：** 办公室白板——大家都能看，比翻档案柜（MySQL）快，但容量小、断电可能丢（需持久化策略）。

**你怎么用？【项目】**  
- **新闻推荐**：推荐候选 List、热门榜 ZSet、用户偏好  
- **数仓**：维表热点缓存，减轻 HBase 压力  
- **百味智厨**：`cache-learning` 模块多级缓存 L2  

**面试口述版：**  
> Redis 是内存缓存，我用来放热点、减轻数据库压力。推荐项目里存用户推荐列表和热门榜；数仓里缓存维表热点；还了解穿透、击穿、雪崩和过期策略。和 Caffeine、Redisson 配合做多级缓存和分布式锁。

**子技能：**

| 名词 | 通俗解释 |
|------|----------|
| **分布式缓存** | 多台服务器共用一个 Redis，缓存共享 |
| **String/List/Hash/Set/ZSet** | 五种数据结构；推荐常用 List（列表）和 ZSet（排行榜） |
| **RDB/AOF** | 两种持久化：快照 / 写日志，防止重启全丢 |
| **过期策略** | 到时间自动删；定期+惰性删除 |

---

### 2.3 Caffeine

**是什么？**  
**JVM 进程内**的高性能本地缓存库，比老 Guava Cache 更常用，速度极快，但别的机器看不到。

**类比：** 你桌上的便签——自己看最快，同事看不到。

**你怎么用？【项目】**  
- `MultiLevelCacheService`：L1 Caffeine → L2 Redis → DB  

**面试口述版：**  
> Caffeine 是本地缓存，放在应用进程里，读最快。我和 Redis 组成多级缓存：先查 Caffeine，没有再查 Redis，再没有查数据库，查到后回填上层，减少 Redis 和 DB 压力。

---

### 2.4 Redisson

**是什么？**  
基于 Redis 的 **Java 客户端增强包**，封装了**分布式锁**、集合、对象等，不用手写 SETNX。

**类比：** Redis 上的「智能锁」，带自动续期，防止业务没跑完锁就过期。

**你怎么用？【项目】**  
- `DistributedLockService`：演示多实例下对同一资源加锁  

**面试口述版：**  
> Redisson 在 Redis 上实现分布式锁。多实例同时改同一数据时，先 tryLock，执行业务再 unlock。它比手写 SETNX 方便，有看门狗续期。我在学习模块里用它做过库存扣减示例；数仓/推荐里 Redis 更多做缓存和召回。

---

### 2.5 多级缓存

**是什么？**  
多层缓存组合：**本地（Caffeine）→ 分布式（Redis）→ 数据库**，逐级查、逐级回填。

**类比：** 先翻口袋 → 再查办公室白板 → 最后去档案室。

**面试口述版：**  
> 多级缓存就是 L1 本地、L2 Redis、L3 DB。热点在 L1 挡掉，L1 没有才打 Redis，再没有才查库，查完反向写入，兼顾速度和一致性。

## 三、大数据与后端框架

### 3.1 Hadoop 生态

#### HDFS

**是什么？**  
Hadoop **分布式文件系统**，大文件切块存多台机器，适合存日志、原始数据。

**类比：** 一个超大网盘，文件切成块分散存，坏一块能副本恢复。

**通俗答：** 数仓 ODS 原始数据常落 HDFS；NameNode 管目录，DataNode 存块。

---

#### MapReduce

**是什么？**  
Hadoop 早期 **编程模型**：Map 拆分计算，Reduce 汇总结果。

**类比：** 分班改试卷（Map），再汇总分数（Reduce）。

**通俗答：** 现在更多用 Spark 替代，但理解 MR 有助于懂「分而治之」和 shuffle 概念。

---

#### YARN

**是什么？**  
Hadoop **资源调度器**，负责给 MapReduce、Spark 等任务分配 CPU 和内存。

**类比：** 机房管理员，谁要跑任务就分配机器资源。

**通俗答：** 集群上 Spark/Flink 任务提交后，由 YARN 分配 Container 运行。

---

### 3.2 Hive

**是什么？**  
在 HDFS 上的 **「用 SQL 查大数据」** 工具，把 SQL 转成 MapReduce/Spark 任务。

**类比：** 大数据上的「方言 SQL」，表数据其实在 HDFS 文件里。

**子技能：**

| 名词 | 通俗解释 |
|------|----------|
| **HSQL / HiveQL** | Hive 的 SQL 语法，类似 MySQL 但有分区等扩展 |
| **开窗函数** | 在不合并行的前提下做排名、累计，如 `row_number()`、`sum() over()` |
| **Explain** | 看 Hive 怎么执行这条 SQL，有没有全表扫 |
| **Join 优化** | 小表放 Map Join 广播，大表和大表 Join 注意 shuffle |
| **Shuffle 调优** | 数据跨节点重分区，最耗性能；减少 shuffle、合理分区 |

**面试口述版：**  
> Hive 我用来建 ODS-DWD-ADS 分层表，写 HSQL 做 ETL。会用开窗函数做排名和累计，用 Explain 看计划，Join 时小表广播，并注意 shuffle 和数据倾斜。

---

### 3.3 Spark

**是什么？**  
**内存计算**大数据框架，比 MapReduce 快，适合离线 ETL、机器学习、**Spark Streaming** 微批流。

**类比：** 数据先在内存里算，算不动再落盘，批量处理很快。

**子场景：**

| 场景 | 通俗解释 | 【项目】 |
|------|----------|----------|
| **Spark SQL** | 用 SQL 做 ETL 和指标 | 数仓 DWD/ADS |
| **Spark Streaming** | 小批次连续处理流数据 | 新闻推荐消费 Kafka 更新偏好 |
| **数据倾斜** | 某 key 数据特别多，一个 task 拖死 | 加盐、广播小表 |

**面试口述版：**  
> Spark 我用于离线数仓 ETL 和新闻推荐的 Spark Streaming。离线用 Spark SQL 做分层和指标；实时用 Streaming 消费 Kafka 更新用户偏好和 Redis 候选。了解宽窄依赖、shuffle 和倾斜处理。

---

### 3.4 Flink

**是什么？**  
**真流式**计算引擎，低延迟，适合 CDC、实时 Join、窗口聚合。

**类比：** 自来水管里的水来一条处理一条；Spark Streaming 更像「每隔几秒接一桶」。

**子技能：**

| 名词 | 通俗解释 | 【项目】 |
|------|----------|----------|
| **DataStream** | 流式 API | 实时数仓 |
| **Flink CDC** | 读 MySQL binlog 实时同步 | 维表同步 |
| **广播流** | 小流复制到所有并行任务 | 维表变更下发 |
| **Watermark** | 允许数据迟到多少 | 处理乱序 |
| **Interval Join** | 两流在时间差范围内才匹配 | 事实+维表关联 |
| **Checkpoint** | 快照容错，挂了能恢复 | 任务稳定性 |

**面试口述版：**  
> Flink 我做实时数仓：CDC 同步 MySQL 维表，广播流更新维度，Interval Join 关联事实流，结果写 HBase、Redis、Doris。理解水位线和 checkpoint。

---

### 3.5 Azkaban

**是什么？**  
**任务调度**平台，按 DAG（有向无环图）定时跑 Hive/Spark 等任务，有依赖关系。

**类比：** 闹钟 + 流程图——先跑 A 再跑 B，失败可告警重试。

**面试口述版：**  
> Azkaban 用来调度离线任务，配置任务依赖和 cron，数仓 ETL 和 ADS 指标任务跑完后通知下游或 Power BI 刷新。

---

### 3.6 生态组件

#### Flume

**是什么？**  
**日志/数据采集**工具，Agent 从源（文件、端口）收集数据送到 HDFS/Kafka。

**类比：** 漏斗收集散落的日志，统一倒进大数据管道。

---

#### Sqoop

**是什么？**  
在 **关系库（MySQL）和 HDFS/Hive** 之间**批量导入导出**。

**类比：** 数据库和大数据之间的「搬家卡车」。

---

#### Zookeeper（ZK）

**是什么？**  
**分布式协调**服务：选主、配置同步、分布式锁（旧方案）。

**类比：** 小组长，大家听它的状态（谁当 leader、配置是什么）。

**通俗答：** Kafka 旧版依赖 ZK；Hadoop 高可用也常用 ZK。

---

#### Kafka

**是什么？**  
**高吞吐消息队列**，生产者写 Topic，消费者按组消费，解耦和削峰。

**类比：** 传送带上的包裹，多个工人（消费者组）按规则取。

**【项目】** 新闻行为流；数仓实时采集。

**面试口述版：**  
> Kafka 做行为数据和实时管道。新闻里埋点发 Kafka，Spark Streaming 消费；解耦前端写入和实时计算，支持多消费者。

---

#### ClickHouse

**是什么？**  
**列式 OLAP** 数据库，分析查询极快，适合日志分析、大屏统计。

**类比：** 为「统计报表」优化的数据库，单行查询不如 MySQL，聚合分析很强。

**通俗答：** 和 Doris 类似场景；简历列了 ClickHouse，数仓项目里 Doris 做 OLAP，可说明「列存 OLAP 都了解，项目用 Doris」。

---

### 3.7 云平台：MaxCompute、DataWorks

| 组件 | 通俗解释 | 面试怎么说 |
|------|----------|------------|
| **MaxCompute（ODPS）** | 阿里云**离线大数据计算和存储**，SQL 跑海量数据 | 云上数仓计算引擎，类似 Hive+Spark 的云版 |
| **DataWorks** | 阿里云**数据开发平台**：集成、调度、运维、数据地图 | 在网页上编排任务、监控实例；可配合 OpenAPI/SDK 触发作业 |

**面试口述版：**  
> MaxCompute 负责云上离线计算和存储；DataWorks 负责开发、调度、运维一体化。我掌握基础使用：建表、写 SQL、配工作流调度，了解 OpenAPI/SDK 做任务触发和状态查询。

---

### 3.8 Spring AI

**是什么？**  
Spring 官方出的 **AI 应用开发框架**，统一对接大模型、RAG、工具调用、Advisor 等。

**类比：** Spring Boot 之于 Web；Spring AI 之于「接大模型做应用」。

**核心词：**

| 名词 | 通俗解释 |
|------|----------|
| **ChatClient** | 调大模型的统一客户端 |
| **ChatModel** | 模型抽象（如 qwen-plus） |
| **Advisor** | 对话前后增强：记忆、RAG、日志 |
| **VectorStore** | 存向量、做相似检索 |
| **Tool Calling** | 让模型决定调哪个 Java 函数 |
| **MCP** | 标准化连接外部工具/服务 |

**【项目】** 百味智厨全链路。

**面试口述版：**  
> Spring AI 是 Spring 生态的 AI 框架。我用 ChatClient 调模型，Advisor 挂记忆和 RAG，VectorStore 存菜谱向量，@Tool 做本地工具，MCP Client 接生图服务，整体在 Spring Boot 里集成。

---

### 3.9 Spring AI Alibaba

**是什么？**  
Spring AI 的**阿里云扩展**，对接**百炼 DashScope**（通义千问等）。

**类比：** Spring AI 是通用插座；Spring AI Alibaba 是「国标转阿里云」的转接头。

**【项目】** `spring-ai-alibaba-starter-dashscope`，`dashScopeChatModel`。

**面试口述版：**  
> Spring AI Alibaba 把通义/百炼接到 Spring AI 里，配置 api-key 和 model 就能注入 ChatModel 和 EmbeddingModel，我项目里用的是 qwen-plus。

---

### 3.10 LangChain4j ⚠️

**是什么？**  
Java 版 **LangChain**，另一套 AI 应用框架，和 Spring AI **平行**，API 不同。

**【项目】** 百味智厨**未使用**；简历写了建议面试说：

**面试口述版（诚实）：**  
> LangChain4j 我了解它是 Java 上另一套 Agent/RAG 框架；我实际项目用的是 **Spring AI**，因为和 Spring Boot 集成更顺。LangChain4j 的概念如 Chain、Tool 和 Spring AI 类似，可以迁移理解。

---

### 3.11 Spring Boot

**是什么？**  
快速搭建 **Java Web 应用**的框架：内嵌 Tomcat、自动配置、starter 依赖。

**类比：** 精装房毛坯变可住，少写 XML 配置。

**【项目】** 新闻推荐、百味智厨后端。

**面试口述版：**  
> Spring Boot 做 REST 服务。Controller 接请求，Service 写业务，Mapper 访问数据库；自动配置数据源、JSON 序列化；百味智厨还集成 Spring AI 和 JWT 拦截器。

---

### 3.12 MyBatis / MyBatis-Plus

**是什么？**  
**ORM 框架**，Java 对象和 SQL 映射；MyBatis-Plus 加了 CRUD 封装、条件构造器。

**类比：** Java 方法和 SQL 之间的「翻译官」。

**【项目】** 简历写 MyBatis；百味智厨用 **MyBatis-Plus**（`BaseMapper`、`LambdaQueryWrapper`）。

**面试口述版：**  
> MyBatis 负责 SQL 和 Java 映射。项目里用 MyBatis-Plus，继承 BaseMapper 做增删改查，复杂 SQL 用 XML 或注解；实体和 DTO 分开，配合 Lombok。

---

### 3.13 RESTful API

**是什么？**  
用 **HTTP 方法**表达操作：GET 查、POST 增、PUT 改、DELETE 删；URL 表示资源。

**类比：** 统一的「办事窗口规则」，大家按同一套约定调接口。

**【项目】** `/api/auth/login`、`/api/chat/conversations`、`/api/ai/chef_app/chat/sse`。

**面试口述版：**  
> 接口按 REST 设计，资源用名词路径，状态码表示结果；返回 JSON；联调用 Postman 和 Knife4j 验证参数和异常场景。

---

### 3.14 Postman

**是什么？**  
**HTTP 接口调试**工具，发请求、看响应、保存集合。

**类比：** 接口的「试键器」，不用写前端先测后端。

**面试口述版：**  
> 开发完接口用 Postman 测正常和异常参数，测登录 token、推荐接口、埋点接口；也会导出集合给前端对照。

---

### 3.15 Cursor

**是什么？**  
带 **AI 辅助** 的代码编辑器，用自然语言生成/改代码，提高前端和后端开发效率。

**【项目】** 简历写用 Cursor 开发前端；百味智厨 Vue3 界面。

**面试口述版：**  
> Cursor 是 AI 编程工具，我在做 Vue3 前端时用 AI 辅助写页面和调 API，加快布局和业务联调，但核心逻辑和接口设计仍自己把控。

---

### 3.16 ECharts

**是什么？**  
百度开源的 **前端图表库**，折线、柱状、饼图、**词云**等。

**【项目】** 新闻推荐：词云、活跃度、时间分布。

**面试口述版：**  
> ECharts 做新闻后台可视化，前端 init 图表，后端接口返回统计 JSON，词云展示热词，折线图看活跃度和时间分布，数据和 SQL 聚合结果对齐。

---

### 3.17 Power BI

**是什么？**  
微软 **商业智能**工具，连接数据源做报表、看板、拖拽分析。

**【项目】** 数仓 ADS 层指标可视化。

**面试口述版：**  
> 数仓 ADS 指标导入 Power BI，做管理层看板，支持按时间、产线等维度筛选；我负责指标 SQL 和字段口径，看板配置参与对接。
